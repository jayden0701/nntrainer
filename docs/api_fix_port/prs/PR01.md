# PR 1 — V-JEPA2 QNN 출력 버퍼 안전성

## 목적

과거 `api_fix`의 V-JEPA2 QNN 출력 버퍼 수정 의도는 유지하되, 현재
브랜치의 입력 계약과 QNN tensor metadata를 기준으로 다시 구현한 독립
안전성 수정이다. 출력 tensor의 원소 폭이 입력 dtype과 다를 때 잘못된
크기로 버퍼를 할당하거나 잘못된 stride로 requantize하던 문제를
바로잡는다.

- 기준 커밋: `0e5a913c1978c0b72b78598ec1e0464d1513d6af`

## 변경 범위

변경 파일은 다음 하나뿐이다.

- `Applications/CausalLM/qnn/vjepa2-qnn/vjepa2_qnn.cpp`

주요 변경은 다음과 같다.

- destination dtype의 원소 폭으로 출력 버퍼 크기와 stride를 계산한다.
- 입력·출력 포인터, tensor rank와 dimension, shape 곱셈 overflow를
  검증한다.
- 임시 출력 버퍼를 RAII로 소유하여 예외 경로에서도 누수를 막는다.
- requantization을 사용하는 경우 출력 tensor가 지원하는 unsigned
  fixed-point dtype인지 검증한다.
- raw video와 preprocessed tensor 입력의 크기가 같은 `auto` 모드에서는
  기존 동작대로 preprocessed 입력을 우선한다.

## 비판적 수용과 제외

과거 커밋 `e1a7d2bc`의 destination-width 수정은 수용했지만, 과거 코드의
“multiple inference” 해석은 그대로 가져오지 않았다. 앞단의 정확한
byte-size gate는 한 번에 표준 video clip 하나만 허용하므로, 이를
명시적인 one-video-clip 계약으로 정리했다. 또한 과거 패치에 없던
rank/dimension/overflow 검증을 추가했다.

즉, 이 PR은 과거 diff를 기계적으로 이식한 것이 아니라 현재 입력
계약과 일치하도록 범위를 좁힌 수정이다.

## 이 환경에서 수행한 검증

- 변경 C++ 파일에 clang-format 14를 적용했다.
- `git diff --check`를 수행했다.
- 입력 layout, tensor metadata, allocation ownership과 변환 경로를
  정적으로 검토했다.
- configure, compile, unit test, QNN runtime 실행은 하지 않았다.

## 외부 환경에서 필요한 검증

- QAIRT/QNN SDK가 준비된 x86 Linux 또는 지원 대상 환경에서 QNN-enabled
  compile/link를 확인한다.
- raw video와 preprocessed tensor 각각의 정상 입력을 실행한다.
- 잘못된 rank/dimension, null buffer, 크기 overflow 입력이 안전하게
  거부되는지 확인한다.
- 출력 dtype별 requantization 결과와 버퍼 경계를 sanitizer 또는 동등한
  도구로 확인한다.
- raw와 preprocessed byte size가 같은 `auto` 입력에서 기존
  preprocessed 우선 동작을 확인한다.

## 의존성과 후속 작업

이 PR은 다른 이식 변경에 의존하지 않는 첫 번째 스택이다. PR2는 이
수정을 보존하면서 V-JEPA2의 추가 shape·quantization 검증과 native
request-scoped API를 함께 도입한다. 실제 QNN runtime 결과가 확인되기
전까지 “multiple inference 지원”을 주장해서는 안 된다.
