# PR14 — 모호한 QNN RPC memory 상태의 즉시 quarantine

## 목적

PR13이 shutdown 시점의 자원 순서를 완결했다면, 이 PR은 런타임 중
`rpcmem_alloc`, `memRegister`, `memDeRegister` 결과가 모호해진 순간 새
실행·할당 admission을 닫는다. vendor가 중복 non-null memHandle을 반환하는
경우 tensor에 게시하기 전에 전체 ledger에서 alias를 검출하고, 정상
MemoryPool free도 첫 vendor call 전에 전체 구조를 검사한다.

## quarantine·transaction 설계

`QUARANTINED`는 복구를 추정하지 않는 sticky terminal 상태다. 실행 중 fault는
shared execution lease를 가진 채
`RUNNING | SHUTDOWN_REQUESTED -> QUARANTINED` atomic CAS로 admission을
닫는다. shared lease를 exclusive cleanup lease로 승격하지 않으므로
deadlock을 만들지 않는다. shutdown thread는 exclusive gate 획득 뒤 상태를
다시 읽고, 정상 완료도 오직
`SHUTDOWN_REQUESTED -> SHUT_DOWN` CAS만 허용해 concurrent fault를
덮어쓰지 않는다.

RPC 결과는 다음처럼 보수적으로 분류한다.

- `rpcmem_alloc`의 null 반환은 명확한 allocation failure다.
- `rpcmem_alloc` throw는 획득 여부를 알 수 없으므로 null-key quarantine
  placeholder와 admission closure를 기록한 뒤 원래 예외를 다시 던진다.
- 이미 live인 pointer가 다시 반환되면 기존 allocation까지 quarantine하고
  두 번째 획득을 임의로 free하지 않는다.
- `memRegister`는 문서화된 request/mapping 계열 error와 null output만 clean
  failure로 본다.
- `ALREADY_REGISTERED`, invalid context, 예상 밖 error와 null,
  throw, `error + non-null`, `success + null`은 backing과 관찰한 handle을
  보존하고 lifecycle을 닫는다.
- non-null output은 tensor에 게시하기 전에 manager 전체 ledger에서
  allocation 없이 선형 검사한다. alias가 있으면 모든 owner와 allocation을
  함께 quarantine한다.

일반 `free()`와 shutdown drain은 첫 `memDeRegister` 전에 대상 전체와
manager-wide alias를 검사한다. null context/handle, 비-ACTIVE 상태, invalid
fd, missing function 또는 ledger invariant 위반이 있으면 vendor call을
시작하지 않고 backing을 보존한다. deregister error/throw 뒤에는 재시도하지
않는다.

## 비판적 검토와 수용 판단

- 초기 구상처럼 shared reader가 exclusive gate로 upgrade하도록 만들면
  deadlock 가능성이 있다. 따라서 현재 lease 안에서 가능한 atomic terminal
  전이로 설계를 바꿨다.
- fault 전에 lease를 얻고 RPC mutex에서 대기하던 reader도 mutex 진입 직후
  lifecycle을 재검사한다. 이를 생략하면 quarantine 뒤에 새로운 vendor call이
  시작될 수 있다.
- error 분류는 추측이 아니라 역사상 vendored QAIRT
  `v2.47.0.260601`의 `QnnMem.h` 계약을 직접 확인해 정했다. clean rollback
  범위를 넓히지 않고, 기존 또는 유실 registration을 뜻할 수 있는 결과는
  보수적으로 보존한다.
- alias와 structural invalidity가 동시에 있더라도 실제 충돌 owner를 모두
  ledger에서 quarantine한다. 단순히 error만 반환하고 ACTIVE owner를
  남기지 않는다.
- graph execute gate, op-package hook, alignment/range/duplicate-fd identity는
  이 두 파일의 RPC fault 범위를 넘으므로 후속 PR로 분리했다.

## 외부 환경에서 필요한 검증

- QAIRT 2.47 SDK를 사용하는 QNN-enabled x86 Linux compile/link
- `rpcmem_alloc`, `memRegister`, `memDeRegister`, `rpcmem_free` 결과별
  failure injection과 ledger/resource report
- 동일 handle을 둘 이상의 context 또는 signature에 반환하는 alias injection
- active reader의 RPC fault와 QNNContext shutdown 경쟁
- 정상 pool release 뒤 allocation/registration count가 모두 0인지 확인
