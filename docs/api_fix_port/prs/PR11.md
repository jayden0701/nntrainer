# PR 11 — 복구 가능한 QNN RPC resource 관리

## 목적

QNN RPC allocator의 process 종료형 실패 처리와 불명확한 resource
ownership을 제거한다. backend DSO, rpcmem allocation과 descriptor별 QNN
registration을 명시적 ledger로 추적하고, 확실히 정리할 수 없는 상태는
예외 없는 cleanup 경로에서 보존한다.

## 핵심 불변식

- RPC manager는 `libQnnHtp.so`를 다시 열거나 provider를 다시 고르지 않는다.
  `QNNContext`가 선택한 interface table을 값으로 복사하고 backend DSO의
  shared lifetime token을 QNNVar와 allocator가 함께 보유한다.
- lifetime token control block 생성 실패로 DSO가 닫히면 raw handle과
  복사된 function table도 즉시 무효화하여 unloaded function pointer를
  호출하지 않는다.
- allocation ledger는 exact base pointer, size, cached fd와 상태를
  기록한다. host node를 `rpcmem_alloc` 전에 예약하고, vendor가 live
  pointer를 중복 반환하면 기존 및 새 allocation을 격리하고 추가 할당을
  sticky하게 차단한다.
- registration identity는 allocation, context, dtype, dimensions와 required
  bytes 전체다. 같은 pointer/context라도 descriptor가 다르면 별도 handle을
  요청하고 stale handle을 임의 재사용하지 않는다.
- `memRegister`의 error+null만 clean failure로 pending node를 제거한다.
  error+nonnull, success+null 또는 throw는 완료가 불명확하므로 registration
  및 backing을 보존한다.
- `free()`는 `MemoryPool` destructor 경로를 위해 `noexcept`이다. 각
  deregistration 성공 node만 지우고 첫 실패 뒤 추가 vendor call을 멈춘다.
  unknown 또는 interior pointer는 `rpcmem_free`하지 않는다.
- manager destructor는 context의 생존을 가정해 QNN API를 호출하지 않는다.
  registration이 없는 확실한 allocation만 process-lifetime RpcMem loader로
  정리하고 나머지는 보존한다.

## 비판적 검토와 범위 결정

기존 manager가 backend DSO를 독립적으로 다시 열고 provider를 다시
선택하면 Context와 allocator가 서로 다른 function table과 unload 수명을
가질 수 있다. 이를 편의상 유지하지 않고 최초 선택의 shared ownership으로
통일했다.

allocation pointer만 key로 쓰면 MemoryPool temporal alias와 descriptor
차이를 구분하지 못한다. 반대로 vendor의 `ALREADY_REGISTERED`를 성공처럼
재사용하면 어떤 descriptor의 handle인지 증명할 수 없으므로 명시적
실패를 선택했다.

PR11의 context별 live registration count는 snapshot이다. concurrent
forwarding이 그 직후 새 registration을 만들 수 있으므로 이 PR만으로
teardown race가 해결됐다고 주장하지 않는다. 공통 execution lifecycle
gate는 PR12의 의도된 후속 범위다.

## 이 환경에서 수행한 검증

- 초기 설계 감사 3개와 수정 후 compile/API, ledger state 및
  lifetime/lock-order 감사 3개를 read-only로 수행했다.
- QAIRT 2.47/QNN API 2.36 signature와 C++17 node-handle/noexcept 규칙을
  정적으로 대조했다.
- clang-format 14.0.6 strict dry-run과 `git diff --check`를 확인했다.
- PR10 ancestry, DCO/Codex trailer와 `subprojects/` 무변경을 확인했다.
- configure, compile, unit test, Gradle, Android와 runtime은 실행하지
  않았다.

## 외부 환경에서 필요한 검증

- QNN-enabled Android/arm64를 compile한다. native x86 Linux 기본 build가
  이 target을 포함하는지는 후속 native plugin target 변경과 함께
  확인한다.
- 동일 allocation을 같은/다른 context 및 같은/다른 descriptor로 등록해
  identity와 handle 재사용 거부를 검증한다.
- `rpcmem_alloc`, fd 변환, `memRegister`와 `memDeRegister`의 각
  failure/throw/output 조합을 주입해 report, quarantine과 backing 보존을
  확인한다.
- normal pool deallocate 뒤 registration 및 allocation count가 0인지
  확인한다.
- duplicate/interior pointer 반환에서 잘못된 free나 process 종료가
  발생하지 않는지 확인한다.

## 의존성과 후속 작업

PR10의 호출별 descriptor ownership과 전역 graph deregistration 제거에
의존한다. PR12는 forwarding/alloc과 context/allocator/runtime cleanup
사이에 공통 shared/exclusive lease를 추가한다. PR13은 known registration을
context보다 먼저 drain하고 전체 vendor teardown 순서를 완성한다.
