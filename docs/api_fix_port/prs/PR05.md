# PR 5 — Legacy API 정리와 unified API 문서화

## 목적

PR2~PR4에서 새 API와 모든 주요 소비자를 먼저 준비한 뒤, superseded
generation/session/config 경로를 제거하고 공개 C header와 사용자 문서를
실제 unified API 계약에 맞춘다. 호환성 파괴 코드와 문서 변경을 같은
브랜치의 두 개 주제별 커밋으로 분리했다.

## 핵심 설계 판단

- 공개 generation surface를 exact formatted text의
  `quickAiRunText()`와 templated/request-scoped
  `quickAiRunOpenAI()`로 제한한다.
- `quick_dot_ai_api.h`를 독립적으로 install 가능한 C header로 만들고
  fixed-width type, callback typedef와 Windows build/consumer export를
  직접 정의한다.
- 비활성 `if (0)` in-memory config loader, mutable global registry와
  global lock을 제거한다. 실제 loader는 file-based 경로만 사용한다.
- `kv_len`, `native_lib_dir`, `last_output`, session update/reset helper,
  descriptor의 미사용 필드와 비어 있던 same-build callback registry를
  제거한다.
- retained C entry가 mutex/allocation exception을 C ABI 밖으로 내보내지
  않도록 하고 embedding result는 RAII로 소유한다.
- CLI의 일반 prompt는 escaped OpenAI request를 사용하고, 사용자가
  명시적으로 exact input을 선택한 경우에만 `quickAiRunText()`를
  사용한다.
- 문서는 실제 Android packaging, process-wide QNN config, Native/LiteRT
  capability 차이와 load/unload 소유권을 기술한다.

## 비판적 수용과 제외

legacy API 삭제는 과거 patch처럼 이식 초기에 수행하지 않았다. PR2에서
additive API를 도입하고 PR3에서 Android 소비자를 옮기며 PR4에서
extension 경계를 준비한 뒤에만 삭제했다. 그럼에도 이 PR은 명시적인
source/binary compatibility break이다.

Kotlin의 `modelKey`와 실제로 forwarding되지 않던
`htpBackendConfigPath` 제거도 AAR source/binary 및 serialized-wire
호환성 파괴다. downstream은 재컴파일해야 하며 옛 serialized key에
의존하면 안 된다.

과거 내부 handoff 문서인 `QUICK_DOT_AI_API_FIX_STATUS.md`와 그 안의
build/test 성공 주장은 제품 patch에 포함하지 않았다. root README의
성능표, Windows 설명, Android option, quantization과 safetensors 정보는
보존하면서 obsolete API 부분만 다시 썼다.

## 이 환경에서 수행한 검증

- 변경 C/C++ source/header 8개에 clang-format 14.0.6을 적용하고 strict
  dry-run을 확인했다.
- `git diff --check`를 수행했다.
- 제거된 legacy symbol, source manifest/header ownership, Kotlin/JNI
  선언 대응과 Markdown fence를 정적으로 검색했다.
- 누적 PR1~PR5 ancestry, DCO sign-off와 Codex co-author trailer,
  `subprojects/` 무변경을 확인했다.
- configure, compile, unit test, Gradle, Android와 runtime은 실행하지
  않았다.

## 외부 환경에서 필요한 검증

- x86 Linux에서 `libcausallm`, API DSO와 smoke CLI를 build/link하고 두
  공개 generation API를 실행한다.
- 설치된 public header를 독립 C/C++ consumer에서 include/link한다.
- exact text와 OpenAI prompt가 서로 다른 template 의미를 보존하는지
  확인한다.
- downstream Android 앱을 새 AAR로 재컴파일하고 삭제된 Kotlin field와
  serialized key migration을 확인한다.
- Native/LiteRT/QNN별 문서 명령과 unload-then-destroy 순서를 실제
  artifact에서 확인한다.
- 의도적으로 삭제된 legacy symbol에 의존하는 binary가 실패하는 범위를
  release note에서 고지한다.

## 의존성과 후속 작업

커밋은 별도 review 단위이지만 문서 커밋은 코드 커밋 위에 쌓인다.
PR6에서 Windows source gate, Linux install cluster와 Android link
dependency를 재검토한다.
