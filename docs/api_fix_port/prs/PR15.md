# PR15 — 생성 BackendExtensions의 DSO 소유권과 안전한 teardown

## 목적

QAIRT SDK에서 복사해 생성하는 BackendExtensions wrapper가 extension
interface와 DSO를 명시적으로 소유하도록 고친다. 정상 종료와 wrapper가 직접
판별한 생성 실패에서는 안전하게 정리하고, 외부 DSO 코드의 예외처럼 결과가
모호한 경우에는 잘못 unload하지 않고 QNN runtime 전체를 보존한다.

## teardown·생성 계약 설계

생성되는 BackendExtensions wrapper는 extension DSO를 `dlOpen()` 직후부터
member로 소유하고 copy/move를 금지한다. idempotent하고 sticky한
`shutdown() noexcept`를 제공하며, interface destroy가 정상 반환한 뒤에만
DSO를 닫는다. destroy 또는 `dlClose`의 error/throw는 재시도하지 않고
실패 상태와 owner를 보존한다.

wrapper가 정상 반환값을 검사해 직접 만드는 deterministic constructor
failure는 throw 전에 shutdown을 시도한다. 반면 factory나 hook 자체가
던지는 임의 예외는 DSO-defined exception object 또는 typeinfo가 unwind
중일 수 있으므로 DSO와 숨은 interface state를 process lifetime 동안
의도적으로 보존한다.

`QNNContext`는 extension owner를 reset하기 전에 `shutdown()` 결과를
확인한다. 실패하면 PR13에서 마련한 self-reference quarantine으로 extension,
ResourceManager, backend DSO와 나머지 dependency chain을 함께 유지한다.

생성기는 필요한 SDK 파일과 디렉터리를 mutation 전에 모두 검사한다.
QAIRT 2.47.0.260601의 `BackendExtensions.hpp/.cpp` source shape에 대해
transform anchor의 정확한 개수를 요구하고, 새 선언·정의·rollback site와
legacy pattern 부재를 postcondition으로 검증한 뒤에만 revision 2
compatibility stamp를 쓴다. Meson은 `QnnCommon.h`와 이 stamp가 모두
유효해야 generated tree를 재사용한다.

## 비판적 검토와 수용 판단

- `vendor/` 생성 결과를 직접 고치지 않고 generator compatibility layer를
  수정했다. SDK를 다시 복사했을 때 패치가 사라지는 문제와 vendored
  dependency 직접 수정을 피한다.
- 기존 코드는 DSO handle이 생성자 지역변수였고, interface 생성 뒤
  constructor throw 시 owner를 잃었으며, 외부 destroy 예외가 destructor의
  terminate로 이어질 수 있었다. raw owner의 암시적 copy에 따른
  double-destroy 가능성도 함께 닫았다.
- 외부 예외 경로에서 무조건 `dlClose`하는 것은 정리가 아니라 exception
  metadata를 unload하는 use-after-unload가 될 수 있다. 이 경우 leak보다
  안전한 process-lifetime retention을 선택했다.
- API minor가 같다는 이유만으로 임의 SDK source에 transform을 적용하지
  않는다. exact-count와 postcondition이 어긋나면 fail-closed한다.
- ResourceManager는 DLC create/free truth table과 system DSO라는 별도
  상태 머신을 가지므로 이 PR에 섞지 않고 PR16으로 분리했다.

## 이번 작업에서 실제 수행한 검증

- 역사상 vendored QAIRT 2.47.0.260601 source shape를 기준으로 생성 ownership,
  transform anchor, Android/Meson/C++17 호환성을 독립 read-only 감사
  3개로 확인했다.
- clang-format 14.0.6 strict dry-run, `git diff --check`, PR14 ancestry,
  DCO/Codex trailer, 정확한 4개 파일 범위와 `subprojects/` 무변경을
  확인했다.
- generator, configure, build, unit test, Gradle, Android 및 runtime 실행은
  하지 않았다.

특히 생성기를 실제 실행하지 않았으므로 source transform과 stamp의 동작은
정적 검토 결과이며, 생성된 wrapper의 컴파일 성공을 주장하지 않는다.

## 외부 환경에서 필요한 검증

- 깨끗한 QAIRT 2.47.0.260601 tree에서 generator 실행과 revision 2 stamp
  생성 확인
- deterministic constructor failure별 interface destroy와 DSO close
- factory/hook throw, destroy failure, close failure에서 runtime quarantine과
  DSO 보존 확인
- Android NDK QNN compile/link
- native Linux plugin이 생성 wrapper C++를 실제로 포함하는 경로의
  compile/link. PR17 이전 Linux Meson 경로는 generated tree만 만들고
  wrapper를 컴파일하지 않았다.
