# PR 2 — Request-scoped native 생성 API

## 목적

OpenAI request 파싱, grammar, sampling, cancellation과 출력 상태를 각
model handle과 요청에 귀속시키고, 새 C API를 기존 공개 API와 공존시키는
native 기반 PR이다. CPU CausalLM, LFM2와 QNN 경로가 같은
request-scoped 계약을 따르도록 한다.

## 변경 범위

변경은 다음 서브시스템으로 나뉜다.

- C API와 handle 상태:
  `api/quick_dot_ai_api.{h,cpp}`,
  `api/quick_dot_ai_api_internal.h`, streamer와 descriptor
- OpenAI request:
  `api/openai_request.{h,cpp}` 및 parser 단위 테스트 소스
- xgrammar:
  `api/xgrammar_manager.*`, `api/xgrammar_wrapper.*` 및 단위 테스트 소스
- CPU 모델:
  `models/causal_lm.*`, `models/lfm2/lfm2_causallm.cpp`,
  `models/transformer.h`, `chat_template.cpp`
- QNN 생성:
  `qnn/generate_qnn_utils.*`, `qnn/quick_dot_ai_qnn.*`,
  Gemma4/V-JEPA2 구현과 sampler 단위 테스트 소스
- 빌드 소유권:
  `Applications/CausalLM/meson.build`,
  `app_build/meson.build`

주요 공개 추가 API는 `quickAiRunText()`와
`quickAiRunOpenAI()`이다. 이 단계에서는 downstream 전환을 위해 기존
generation export를 유지했다.

## 핵심 설계 판단

- OpenAI JSON은 엄격하게 parse하고 정규화하며, 지원하지 않는
  `stream=false`, image dispatch와 strict mode를 조용히 무시하지 않고
  거부한다.
- chat template, tokenizer 경로, grammar cache/lease, generation epoch,
  cancellation target을 handle 또는 요청에 귀속시킨다.
- xgrammar cache의 cross-handle 접근은 직렬화하고 grammar 객체는 shared
  lease로 보유한다.
- quantized logits를 제자리 수정하는 기존 mask overload는 source
  compatibility를 위해 남기되, 안전하지 않은 호출은 명시적으로
  거부한다. QNN sampler는 별도 grammar bitmask를 소비한다.
- repetition penalty를 top-k보다 먼저 적용하고 per-model RNG를 사용한다.
  `do_sample=false`는 grammar 제약을 유지하면서 결정적으로 동작한다.
- 현재 target의 LFM2 hybrid KV-placeholder 처리, 즉 K/V가 모두 없는
  layer는 건너뛰되 한쪽만 있는 경우는 거부하는 동작을 보존한다.
- `openai_request.cpp`는 `chat_template.cpp`도 사용하므로
  `libcausallm`이 한 번만 소유한다. API DSO에 중복 컴파일하지 않는다.

## 비판적 수용과 제외

과거 18개 커밋의 순서를 그대로 재현하지 않았다. 과거 중간 상태는
`XGrammarManager::initialize()` signature를 먼저 바꾸고 caller는 나중에
바꾸어 독립적으로 build 가능한 스택이 아니었다. 이 PR에서는 transitional
overload와 consumer 변경을 한 coherent commit에 묶었다.

과거 패치처럼 legacy API를 즉시 삭제하지 않고 additive API로 먼저
도입했다. Android 소비자 전환 전 binary/source 호환성을 먼저 깨는
순서는 거부했다. 고위험 QNN sampler도 과거 구현을 그대로 복사하지 않고
검증 순서, RNG 소유권, grammar mask 소비 방식을 다시 설계했다.

V-JEPA2의 “multiple inference” 주장은 수용하지 않았으며 PR1의
one-clip 계약을 유지했다. image sidecar는 fixed-width V1 형태로
예약했지만 extension dispatch가 준비되는 PR4 전까지 실행을 지원한다고
광고하지 않는다.

## 이 환경에서 수행한 검증

- 변경 C/C++ 파일 29개에 clang-format 14를 적용했다.
- `git diff --check`를 수행했다.
- Doxygen `@author`/`@bug`, 공개 선언과 정의의 일치, conflict marker,
  production source의 단일 소유권을 정적으로 검색했다.
- parser, xgrammar와 sampler용 테스트 소스 및 Meson wiring을 추가했지만
  configure하거나 실행하지 않았다.
- compile, unit test, Gradle, Android, QNN runtime은 실행하지 않았다.

## 외부 환경에서 필요한 검증

- x86 Linux에서 CausalLM/API target을 configure·compile하고 parser와
  xgrammar 단위 테스트를 실행한다.
- OpenAI 정상/오류 request, exact text, cancellation, 연속 요청 간 상태
  격리를 확인한다.
- CPU CausalLM과 LFM2 hybrid 모델에서 KV placeholder와 request reset을
  확인한다.
- QNN SDK 환경에서 sampler 테스트, repetition penalty/top-k/top-p,
  grammar mask, deterministic mode와 cancellation을 확인한다.
- Android source manifest에서도 `openai_request.cpp`가 정확히 한 번
  링크되는지 실제 link 결과로 확인한다.

## 의존성과 후속 작업

PR1 위에 쌓이며 PR3의 JNI/Kotlin 전환을 위한 C API 경계를 제공한다.
PR4가 extension image dispatch를 추가하기 전에는 native image request가
지원되지 않는다. PR5에서 모든 소비자가 전환된 뒤에만 legacy generation
API를 제거한다.
