# PR 10 — QNN graph forwarding 안정화

## 목적

반복 forwarding에서 이전 호출의 tensor pointer가 재사용되던 문제를
제거하고, QNN tensor descriptor의 복사·검증·해제를 예외 안전하게 만든다.
extension config와 graph execution 실패를 caller에 전달하면서 primary
error 진단을 보존한다.

## 핵심 불변식

- 각 forwarding 호출은 현재 NNTrainer tensor의 RPC-backed address를
  직접 binding하며 이전 호출의 input/output pointer vector를 누적하지
  않는다.
- QNN tensor 배열 전체를 `QNN_TENSOR_INIT`으로 초기화한 뒤 deep copy하고,
  동일 SDK의 `freeQnnTensors()`로 정상 및 부분 실패를 정리한다.
- Tensor V1 name, dimensions, data type과 quantization copy 결과를
  검증한다. dimension product overflow, element count와 실제 backing
  capacity도 vendor execute 전에 확인한다.
- NNTrainer와 QAIRT의 nibble 순서가 반대인 UINT4는 별도 packing 변환 없이
  direct bind하지 않고 fail-fast한다.
- `beforeExecute`, graph config, `graphExecute()`와 `afterExecute`의 status
  및 exception을 caller-visible failure로 바꾼다.
- 실제 execute를 시도한 경우 after hook은 한 번 호출하고, execute와 after
  모두 실패하면 execute error를 primary로 유지하면서 after error도
  진단에 남긴다.

## 비판적 검토와 범위 결정

QNNGraph destructor가 모든 RPC registration을 전역 해제하는 기존 동작은
실제 소유자가 graph인지 allocator인지 구분하지 못하므로 제거했다.
정확한 등록 수명과 실패 보존은 PR11의 descriptor-specific ledger로
분리했다.

UINT4를 byte 수만 맞춰 통과시키는 것은 조용한 값 순서 손상을 만들기
때문에 거부했다. 성능을 위해 다시 활성화하려면 명시적인 nibble packing
변환과 round-trip test가 먼저 필요하다.

이 PR의 hook 보장은 실제 execute 시도 전후의 error 전달에 초점을 둔다.
후속 전 스택 감사에서 `beforeExecute` 성공 뒤 local config 준비 또는
`graphSetConfig`가 실패하는 경우의 compensation, graph lifecycle state
복구까지는 완전한 transaction이 아님을 확인했다. 이는 별도의 후속 graph
vendor transaction PR에서 다뤄야 하며 이 문서가 그 보장을 확장해
주장하지 않는다.

## 이 환경에서 수행한 검증

- QAIRT 2.47/QNN API 2.36 signature, C++17과 32-bit overflow 경계를 포함한
  독립 read-only 감사 6개를 수행했다.
- clang-format 14.0.6 strict dry-run과 `git diff --check`를 확인했다.
- PR9 ancestry, DCO/Codex trailer와 `subprojects/` 무변경을 확인했다.
- configure, compile, unit test, Gradle, Android와 runtime은 실행하지
  않았다.

## 외부 환경에서 필요한 검증

- QAIRT 2.47 생성 header로 QNN-enabled x86 Linux와 Android/arm64를
  compile한다.
- FP16, FP32, UFX8과 UFX16 input/output으로 반복 forwarding하여 stale
  pointer가 재사용되지 않는지 확인한다.
- descriptor deep-copy 중간 실패와 dimension/capacity overflow를
  주입하고 leak이나 vendor call이 없는지 확인한다.
- before/config/execute/after 각 단계의 false/error/throw를 주입해 primary
  error와 보조 진단의 우선순위를 확인한다.
- UINT4 model은 packing 변환 구현 전 명시적으로 거부되는지 확인한다.

## 의존성과 후속 작업

PR9의 `ACTIVE` context/graph 게시와 mapping lifetime에 의존한다. PR11은
이 PR에서 제거한 destructor 전역 deregistration을 정확한 allocation 및
descriptor registration ownership으로 대체한다. PR12는 forwarding 전체
수명과 teardown을 배타화한다. config 준비부터 lifecycle state 복구까지의
완전한 vendor transaction은 이후 별도 PR로 남는다.
