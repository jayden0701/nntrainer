# PR 3 — Android backend의 unified API 전환

## 목적

Android QuickDotAI의 session 중심 API를 PR2의 descriptor-bound
`runText()`/`runOpenAI()` 계약으로 전환한다. Native와 LiteRT-LM
adapter, JNI, SampleTestAPP를 함께 이동한 뒤 더 이상 쓰이지 않는 session
adapter와 중복 header를 제거한다.

## 핵심 설계 판단

- Kotlin에서도 OpenAI request를 엄격히 검증하고 image tensor sidecar의
  version과 발생 순서를 유지한다.
- JNI는 PR2의 additive C API만 호출하며, 모든 JNI entry를 C++ 예외가
  경계를 넘지 않는 형태로 감싼다.
- JNI class/method cache의 부분 초기화, native handle, embedding,
  UTF 변환, callback 실패와 unload의 소유권을 명시한다.
- Native QNN/plugin의 optional load 순서와 현재 target의 NDK
  path/revision, `c++_shared`, arm64 ABI, QNN staging 정책을 보존한다.
- LiteRT-LM의 done/error/timeout 경쟁은 한 terminal owner가 결과를
  결정하도록 중재한다. delta와 terminal ordering도 같은 lock 계약을
  따른다.
- SampleTestAPP의 history는 snapshot과 generation check를 사용하여
  close/model 변경 뒤의 stale result가 새 session에 기록되지 않게 한다.
- `api/streamer.cpp`는 `libcausallm`만 소유하고 API DSO에 중복
  컴파일하지 않는다.

## 비판적 수용과 제외

과거 Android patch의 API 전환 의도는 수용했지만, 현재 브랜치의 unified
Meson build와 pinned NDK 전달, CPU-default/optional QNN packaging을
과거 Gradle/Android.mk 내용으로 되돌리지 않았다. 삭제도 먼저 하지 않고
모든 caller를 새 API로 이동한 뒤 obsolete adapter를 제거했다.

이 단계의 versioned image sidecar는 입력 표현만 정의한다. native C
layer의 안전한 extension dispatcher가 아직 없으므로 native image
실행은 의도적으로 지원하지 않는다. 이를 마치 end-to-end multimodal
지원인 것처럼 광고하는 과거 동작은 수용하지 않았다.

## 이 환경에서 수행한 검증

- `quickai_jni.cpp`에 clang-format 14를 적용했다.
- Kotlin native 선언과 JNI symbol/constructor descriptor를 정적으로
  대조했다.
- 삭제된 symbol 참조, source owner, conflict marker를 검색했다.
- `git diff --check`를 수행했다.
- 추가한 JVM 테스트 소스를 포함해 Gradle, Android build, test와 runtime은
  실행하지 않았다.

## 외부 환경에서 필요한 검증

- Android Gradle/AAR build와 추가된 JVM 테스트를 실행한다.
- Native와 LiteRT backend에서 text/OpenAI 정상·오류·취소·timeout을
  확인한다.
- JNI load 실패, callback exception, handle 생성 후 speculative setup
  실패, unload/reload의 누수와 double-free 여부를 확인한다.
- optional QNN artifact가 없는 CPU-only AAR와 QNN-enabled AAR를 각각
  확인한다.
- SampleTestAPP에서 model 변경, Activity 종료와 generation 완료가
  경쟁하는 시나리오를 실행한다.
- image request는 PR4까지 포함한 스택에서만 end-to-end로 검증한다.

## 의존성과 후속 작업

PR2의 additive C API에 의존한다. PR4는 extension ABI와 multimodal
capability enforcement를 추가한다. PR5는 이 PR에서 제거한 session
surface를 참조하는 문서를 갱신하고, 모든 소비자 전환이 끝난 뒤 legacy
native API를 제거한다.
