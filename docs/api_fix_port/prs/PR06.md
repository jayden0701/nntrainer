# PR 6 — 교차 플랫폼 API build/install 정합성

## 목적

PR1~PR5 누적 변경을 독립 재검토하면서 발견한 Windows source manifest,
Linux DSO 설치 위치와 in-tree Android link dependency 불일치를
수정한다. 이 PR은 과거 `api_fix`의 기능 이식이 아니라 이식 결과를
실제 지원 플랫폼 계약에 맞추는 후속 교정이다.

## 핵심 설계 판단

- Windows build에서 source subdirectory가 제외된 cached Qwen/GPT, Tiny
  BERT와 XLM-RoBERTa의 include, registration, descriptor, path와 model
  test source도 동일하게 gate한다.
- Windows+QNN에서 source가 없는 V-JEPA 경로와 descriptor를 광고하지
  않는다.
- non-Windows에서는 `libquick_dot_ai_api`를 기존 `libcausallm` 및 layer
  DSO cluster와 같은 `application_install_dir`에 설치한다.
- in-tree Android의 `libcausallm`과 `libquick_dot_ai_api`에 `liblog`
  dependency를 추가하여 standalone Android build와 맞춘다.
- API README에 실제 installed DSO cluster 위치를 기록한다.

## 비판적 수용과 제외

초기 수정안은 API library의 install 위치를 모든 플랫폼에서 강제로
통일하려 했지만, 독립 검토에서 Windows DLL/import-library의 Meson 기본
배치를 깨는 과도한 변경으로 판단했다. 최종 구현은 non-Windows만 CausalLM
DSO cluster로 모으고 Windows는 기본 install 규칙을 유지한다.

헤더가 우연히 검색된다는 이유로 Windows에서 구현이 제외된 모델을
등록하는 것도 허용하지 않았다. compile만 통과할 수 있어도 생성자와
소멸자 symbol이 `libcausallm`에 없으면 link/runtime 계약이 깨지므로,
source·descriptor·test gate를 함께 정렬했다.

## 이 환경에서 수행한 검증

- 변경 C++ 파일 3개에 clang-format 14를 적용하고 strict dry-run을
  확인했다.
- `git diff --check`를 수행했다.
- Windows source/descriptor/test gate, non-Windows install 경로와 Android
  `liblog` dependency를 독립 read-only diff로 재검토했다.
- PR5 tip이 PR6의 ancestor인지, DCO sign-off와 Codex co-author trailer를
  확인했다.
- configure, compile, unit test, Gradle, Android와 runtime은 실행하지
  않았다.

## 외부 환경에서 필요한 검증

- Windows Meson build에서 API/main/model tests를 compile/link하고 제외된
  model descriptor가 catalog에 나타나지 않는지 확인한다.
- Windows+QNN 구성에서도 V-JEPA를 잘못 광고하지 않는지 확인한다.
- x86 Linux에서 install 후 `libquick_dot_ai_api`가 CausalLM DSO cluster의
  의존성을 loader path 하나로 해결하는지 확인한다.
- in-tree Android build에서 `__android_log_print` 관련 link가
  성공하는지 확인한다.
- shared/static/default-library 조합별로 API target과 install artifact가
  의도한 위치에 생성되는지 확인한다.

## 의존성과 후속 작업

PR5의 breaking cleanup과 문서 tip 위에 쌓인다. PR7은 이 PR의 build
정합성을 전제로 non-Android 기본 model path, backend mask와 Windows
문자열 경계를 수정한다. Linux 배포 packaging이
`application_install_dir`을 별도로 재배치한다면 downstream package의
loader 설정도 함께 확인해야 한다.
