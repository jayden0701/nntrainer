# PR 12 — QNN execution lifetime lease

## 목적

registry lookup 순간만 보호하던 mutex를 넘어, forwarding이 사용하는
context, graph metadata, backend function table과 RPC allocation의 전체
수명을 teardown과 배타화한다. partial initialization과 Context보다 오래
사는 MemoryPool도 같은 shutdown 상태를 공유하도록 runtime lifecycle을
독립 소유 객체로 만든다.

## 핵심 불변식

- `QNNVar`와 `QNNRpcManager`는 별도 `QNNRuntimeLifecycle`을 공동 소유하여
  manager 생성 전 partial init과 late allocator cleanup도 같은 gate를
  사용한다.
- forwarding과 allocation은 shared execution lease를 사용한다. context
  생성·해제, allocator free와 전체 runtime teardown은 exclusive cleanup
  lease를 사용한다.
- shutdown은 exclusive lock을 기다리기 전에 admission을 원자적으로
  닫는다. lock acquisition 자체가 실패하면 상태를 sticky
  `QUARANTINED`로 전환한다.
- lock 순서는 `forwarding_mutex → lifecycle(shared) → context registry →
  RPC ledger`다. queued forward가 reader lease를 먼저 잡지 않고, 하나의
  BackendExtensions before/after pair, profile, graph config와 execute도
  서로 교차하지 않는다.
- context miss에서는 기존 raw reference와 shared lease를 버리고 exclusive
  lease 아래 context를 생성한다. 그 뒤 새 shared lease에서 context와
  graph를 모두 다시 조회하며 unlock 경계를 넘어 raw metadata를 보관하지
  않는다.
- descriptor owner는 execution guard보다 나중에 생성되어 exception
  unwind에서 descriptor가 먼저 정리된다.
- raw context/graph 및 RPC register/count API는 같은 lifecycle이 발급한
  guard를 요구한다.

## 비판적 검토와 범위 결정

단일 registry mutex를 forwarding 전체에 유지하면 기능적으로는 단순하지만
allocator와 teardown의 서로 다른 수명, callback 직렬화 및 lock order를
표현하지 못한다. shared execution과 exclusive cleanup lease를 분리하고,
forwarding mutex를 먼저 잡아 shutdown starvation을 줄이는 방향을
선택했다.

PR12는 종료 결과로 `CLEANUP_PENDING`, `SHUT_DOWN`, `QUARANTINED`를
구분했다. 모든 context가 유효하고 live registration만 종료를 막는
경우에만 self-reference를 둬 late MemoryPool free를 허용하려는
설계였다. 그러나 이후 비판적 감사에서 `CLEANUP_PENDING`을 정상 종료로
완성하는 finalizer가 없어 self-cycle이 영구 잔류할 수 있음을 확인했다.
따라서 이것은 PR12의 완성된 최종 계약이 아니며, PR13에서 known
registration 선제 drain과 즉시 teardown으로 교정된다.

vendor 상태가 모호한 `QUARANTINED`에서는 이후 QNN cleanup을 시도하지
않는다. 확실한 정상 종료 뒤 registration 없는 rpcmem backing만 정리할 수
있다.

## 외부 환경에서 필요한 검증

- active forwarding과 `QNNContext` destruction을 경쟁시켜 dangling
  reference 또는 unloaded function call이 없는지 확인한다.
- 여러 thread의 forwarding 직렬화, queued reader와 shutdown admission
  차단을 검증한다.
- live registration이 남은 context 종료 및 late MemoryPool free를
  PR13까지 포함한 누적 stack에서 확인한다.
- lifecycle/shared/exclusive lock 실패를 주입해 quarantine 이후 QNN vendor
  call이 금지되는지 확인한다.
- ThreadSanitizer 등으로 명시된 lock order와 allocator의 Context 이후
  lifetime을 검증한다.

## 의존성과 후속 작업

PR11의 exact RPC ledger와 shared backend DSO token에 의존한다. PR13은
PR12의 미완성 `CLEANUP_PENDING` path를 제거하고 registration, context,
profile, device, backend, extension, log와 DSO를 dependency 역순으로
teardown한다. 이후 PR14는 live RPC 결과가 모호해진 즉시 runtime admission을
quarantine하는 방향으로 확장한다.
