# PR 4 — Versioned multimodal extension dispatch

## 목적

native multimodal 모델을 안전하게 등록·조회·호출할 수 있는 versioned
extension 경계를 추가하고, C API와 Kotlin catalog가 같은 capability
불변식을 강제하도록 한다. V-JEPA2는 독립 vision encoder로만 광고하며,
검증되지 않은 generic V-JEPA/LFM2 composer는 활성화하지 않는다.

## 핵심 설계 판단

- extension registration table은 C/POD만 사용하며 struct size, ABI
  major/minor, Transformer ABI version, exact build tag와 feature bit를
  포함한다.
- callback은 plain function pointer와 opaque model pointer를 사용한다.
  등록 문자열은 host가 복사하고, lookup은 mutex 밖에서 사용할 value
  snapshot을 반환한다.
- descriptor와 callback publication은 원자적으로 취급한다. 중복 ID,
  architecture와 base/variant namespace 충돌은 overwrite하지 않고
  거부한다.
- plugin 코드는 registry mutex를 잡은 상태에서 호출하지 않는다.
- plugin은 process-lifetime object이며 unload를 지원하지 않는다.
- `quickAiRunOpenAI()`는 image sidecar를 발생 순서와 중복을 보존해
  전달하고, callback 반환값을 최종 결과로 취급한다.
- OpenAI, multimodal, multi-image, vision backend, standalone encoder와
  speculative capability 불변식을 C registry와 Kotlin 양쪽에서
  동일하게 검사한다.
- V-JEPA2 public descriptor는 `VISION_ENCODER`만 광고한다.

## 비판적 수용과 제외

과거 `d6a70ab1`의 callback ABI는 그대로 수용하지 않았다. 과거 형태는
`std::function`, `std::string`, `openai::Request`, `XGrammar`,
virtual `Transformer`를 실제 version handshake 없이 DSO 경계로 넘겼고,
mutex 해제 뒤 무효화될 수 있는 map 내부 pointer를 반환했다. 이를
C/POD와 명시적 크기·버전·build-tag 계약으로 교체했다.

generic V-JEPA/LFM2 composer도 제외했다. 현재 한 경로의 V-JEPA producer는
quantized `uint16_t`를 내지만 LFM2 consumer는 float embedding을 기대하고,
virtual signature와 token-history 계약도 맞지 않는다. 따라서
`vjepa-lfm2` phantom descriptor를 제거하고 이를 end-to-end model로
광고하지 않는다.

이 ABI는 범용 장기 안정 C ABI가 아니라 same-revision/same-build 계약이다.
build tag를 수동으로 올리는 정책과 실제 plugin unload 부재를 사용자에게
숨겨서는 안 된다.

## 이 환경에서 수행한 검증

- 변경한 모든 C/C++ source/header에 clang-format 14를 적용했다.
- duplicate V-JEPA registration, enum 비교, image layout 최소 크기,
  self-alias, Windows export, deterministic catalog ordering과 speculative
  invariant를 정적으로 재검토하고 수정했다.
- `git diff --check`, symbol/source ownership과 Kotlin capability 경로를
  정적으로 확인했다.
- configure, compile, unit test, Gradle, Android와 plugin runtime은
  실행하지 않았다.

## 외부 환경에서 필요한 검증

- 같은 revision으로 host와 mock extension을 build/link하고 정상 등록과
  multimodal dispatch를 실행한다.
- struct size, ABI version, Transformer version와 build tag 각각의 mismatch가
  fail-closed인지 확인한다.
- duplicate ID/architecture, base/variant alias 충돌과 callback 오류를
  주입한다.
- 여러 image와 동일 image의 반복 순서가 callback까지 유지되는지
  확인한다.
- speculative variant의 capability/callback/id 조합을 정상·오류
  케이스별로 확인한다.
- Android Native와 LiteRT가 같은 catalog를 해석하고 standalone encoder를
  generation picker에서 제외하는지 확인한다.

## 의존성과 후속 작업

PR2의 C API와 PR3의 Android adapter 위에 쌓인다. PR5는 이 extension
header와 main API header의 install 경계를 확정하고, 새 API로 모두
전환된 뒤 legacy 경로를 삭제한다. 장기적으로 plugin unload가 필요하면
process-lifetime 가정과 callback/model lifetime 계약을 별도 설계해야
한다.
