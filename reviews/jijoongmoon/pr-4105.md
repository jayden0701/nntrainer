## Review summary

이 PR은 `ComputeOps`에 Tensor 단위 연산을 추가하고 CPU 기준 구현을
제공한다. 또한 FC/Conv2D에 `fused_activation` 속성을 추가하여 일반
forward의 GEMM+bias 뒤에서 activation을 실행한다.

`CpuComputeOps` 추출, 전역 op table 접근자의 out-of-line 이동, 새 CPU
연산 구현을 확인했다. 기존 기본 경로는 CI에서 통과하지만, 새
`fused_activation` 경로는 실행 방식에 따라 의미가 달라지는 두 문제가
현재 head에도 남아 있다.

## Findings

### P1 — FC incremental forward에서 fused activation이 누락됨

위치: `nntrainer/layers/fc_layer.cpp:263`

`FullyConnectedLayer::forwarding()`은 bias 처리 뒤
`apply_activation()`을 호출하지만, 별도의 구현인
`incremental_forwarding()`은 각 `hidden_step`의 matmul/LoRA/bias 처리 후
바로 반복을 끝낸다.

따라서 같은 FC 레이어에 `fused_activation`을 설정하면 일반 forward는
activation된 값을 반환하지만, 토큰 단위 incremental inference는
pre-activation 값을 반환한다. 뒤따르는 `ActivationLayer`를 이 속성으로
대체하는 경우 CausalLM decode 결과가 잘못된다.

각 `hidden_step`의 bias 처리 뒤 동일한 activation epilogue를 적용하고,
일반/incremental forward의 동등성을 테스트해야 한다.

### P1 — 학습 backward에서 activation derivative가 사라짐

위치:

- `nntrainer/layers/fc_layer.cpp:258`
- `nntrainer/layers/fc_layer.cpp:344`
- `nntrainer/layers/conv2d_layer.cpp:483`
- `nntrainer/layers/conv2d_layer.cpp:488`

FC와 Conv2D의 forward는 `fused_activation`을 적용하지만
`calcDerivative()`와 `calcGradient()`는 계속 선형 FC/Conv 출력에 대한
incoming derivative를 그대로 사용한다. 별도 `ActivationLayer`를
제거했다면 그 레이어가 계산하던 activation derivative도 함께 사라진다.

속성이 일반 레이어 property로 노출되고 `training` 여부와 무관하게
forward에서 실행되므로, 학습 그래프에서 이를 사용하면 forward 함수와
gradient가 일치하지 않은 채 조용히 잘못 학습한다.

activation derivative를 FC/Conv backward에 반영하거나, 이 속성과 관련
fusion을 명시적으로 inference-only로 제한해야 한다. 학습 시 수치
gradient 비교 테스트도 필요하다.

## Residual risk

로컬 전체 빌드나 수치 테스트는 다시 실행하지 않았다. 새 whole-op 중
`fused_activation` 외 연산에는 이 PR 안의 실제 caller와 집중 단위
테스트가 없어, later backend가 연결될 때 드러날 shape/data-type 계약
위험은 별도로 남아 있다.
