## Review summary

The two-file unique delta attempts to avoid the ARM KAI QS4CX repack when
CausalLM runs on OpenCL or CUDA. Skipping that work is valid when all consumers
use the plain QS4CX payload, but the new helper reports a requested/build-time
engine rather than the engine of the graph that was actually constructed.

## Finding

### P1 — The guard skips packing for a graph that still uses CPU layers

Locations:

- `Applications/CausalLM/llm_util.hpp:125-142`
- `Applications/CausalLM/models/transformer.cpp:368-372`
- `Applications/CausalLM/models/transformer.cpp:253-256`
- `nntrainer/engine.cpp:91-110`
- `nntrainer/tensor/float_tensor.cpp:1054-1065`
- `nntrainer/tensor/qs4cx_tensor.cpp:91-96`

When `ENABLE_OPENCL` is defined and `NNTR_ENGINE` is unset,
`causallm_engine()` returns `"gpu"`, so `repack_weight()` returns without
packing any QS4CX tensor. However, this head never adds an `engine=` property
to the CausalLM layers: the helper is only referenced by the new repack guard.
`Engine::parseComputeEngine()` therefore routes those engine-less layer
properties to the CPU context.

On ARM, the CPU `FloatTensor::dotQs4cx()` path calls
`input.getPackedData()`. Because the guard skipped `pack()`, that call throws
`"pack before run model"` at the first QS4CX matrix multiplication. An
OpenCL-enabled build with the default environment thus creates a CPU graph but
prepares its weights as if it were a GPU graph. Requesting an unavailable
`NNTR_ENGINE=cuda` has the same mismatch because the helper returns `"cuda"`
without checking the registered contexts, whereas the engine registry falls
back to CPU.

Decide from the actual compiled layer/run contexts, or consistently attach and
validate `engine=<causallm_engine()>` throughout graph construction before
using it to suppress a CPU-required preparation step.

## Residual risk

No ARM/OpenCL runtime was available. The guard also depends on
`ENABLE_OPENCL` being propagated to the application translation unit, so the
opposite mismatch—performing the expensive repack for a real GPU graph—should
be covered once engine routing is wired end to end.
