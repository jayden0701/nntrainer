## 요약

이 PR은 FP16 hidden과 Q6_K weight로 FP16 logit을 계산하는 CUDA lm_head
kernel을 추가한다. 또한 지금까지 정의되지 않은
`NNTR_LLM_CUDA_FAST_PATH` 뒤에 있던 tie-word CUDA 코드를
`ENABLE_CUDA`에서 실제로 활성화한다. 직접 부모 #4123 대비 고유 변경은
3개 파일, 137줄 추가와 10줄 삭제다.

Q6_K의 `ql/qh` bit 해제, scale 선택, 256개 hidden 원소 분담, 홀수 vocab
처리는 기존 OpenCL kernel과 일치한다. 그러나 CUDA 계산 성공 시 함수
전체를 즉시 종료해 bias와 다음 batch를 건너뛴다. 반대로 CUDA 계산이
실패하면 device-only pointer를 CPU fallback이 직접 읽고 써서 충돌할 수
있다. pointer residency와 비동기 실행 오류도 충분히 검증하지 않는다.
이번 gate 변경으로 함께 활성화된 embedding staging은 pinned allocation
실패를 처리하지 않는다.

## 발견 사항

### P1 — CUDA 성공 시 lm_head bias와 나머지 batch를 건너뜀

위치:

- `nntrainer/layers/llm/tie_word_embedding.cpp:619-626`
- `nntrainer/layers/llm/tie_word_embedding.cpp:713-731`
- `nntrainer/layers/llm/tie_word_embedding.cpp:870-877`

Q6_K CUDA kernel이 성공하면 731행에서 `return`한다. 이 코드는 현재
batch의 matrix-vector 계산만 끝낸 상태인데, `return`은 현재 loop가 아니라
`incremental_forwarding_lmhead()` 함수 전체를 종료한다.

그 결과 두 가지 정확성 문제가 생긴다.

1. 아래 공통 후처리의 bias add가 실행되지 않는다. bias가 켜진 layer는
   CPU/OpenCL 결과와 다른 logit을 만든다.
2. `batch > 1`이면 첫 번째 batch 뒤에 함수가 끝나므로 두 번째 batch부터
   출력이 계산되지 않는다.

단순히 `return`을 `continue`로 바꿔도 bias는 여전히 건너뛴다. 현재
batch의 matmul만 완료했다는 `gpu_done` 상태를 두고 공통 후처리까지
도달해야 한다. 특히 device-only output에는 CPU `add_i()`를 바로 쓸 수
없으므로, bias를 CUDA kernel에 포함하거나 device-safe 후처리를 제공해야
한다.

이 문제는 GitHub의 기존 자동 리뷰에서도 지적됐으며 현재 head에도 그대로
남아 있다.

### P1 — device-only 경로에서 CUDA 실패 후 host fallback이 pointer를 직접 역참조함

위치:

- `nntrainer/layers/llm/tie_word_embedding.cpp:713-734`
- `nntrainer/layers/llm/tie_word_embedding.cpp:736-758`
- `nntrainer/layers/llm/tie_word_embedding.cpp:800-820`
- `nntrainer/cuda/cuda_fc_qint4.cpp:1350-1370`

PR 설명과 새 API는 kernel 등록·dispatch에 실패하면 host 계산으로
내려간다고 설명한다. 하지만 이 기능의 핵심 대상인
`NNTR_CUDA_DEV_ACT`에서는 input과 output이 `cudaMalloc()`으로 만든
device-only pointer다.

NVRTC compile, kernel 등록 또는 launch가 실패하면 코드는 736행 이후의
CPU loop로 내려간다. 여기서는 `hin`을 CPU가 직접 FP32로 변환하고,
host GEMV 결과를 `hout`에 직접 쓴다. device-only pointer는 host에서
읽거나 쓸 수 없으므로 fallback이 아니라 access violation 또는
illegal memory access가 된다.

device-only인 경우에는 실패를 명시적으로 전달하거나, input을 D2H
staging하고 결과를 H2D staging하는 실제 fallback을 구현해야 한다.

또한 진입 조건은 `hin`만 `dev_accessible()`로 확인한다. kernel이 함께
사용하는 `weight_data`와 `hout`도 검사해야 한다. CUDA weight allocation만
실패해 일반 host memory로 내려간 경우처럼 세 pointer의 residency가
다르면, host pointer를 kernel에 넘겨 실행 오류가 난다.

현재 wrapper는 `cuLaunchKernel` 제출 성공 뒤 `maybeFinish()`를 호출하고
무조건 `true`를 반환한다. 실제 stream 실행 중 발생한 illegal address는
동기화 결과로 전달되지 않으므로, 이런 경우에는 host fallback마저
건너뛰고 stale logit과 sticky CUDA error를 남길 수 있다. 세 pointer를
모두 검사하고 stream 실행 오류까지 호출자에게 전달해야 한다.

### P2 — 활성화된 embedding staging이 `cudaHostAlloc()` 실패를 무시함

위치:

- `nntrainer/layers/llm/tie_word_embedding.cpp:290-327`
- `nntrainer/layers/llm/tie_word_embedding.cpp:366-375`
- `nntrainer/layers/llm/tie_word_embedding.cpp:411-440`

이 코드는 이전에는 정의되지 않은 macro 뒤에 있어 실행되지 않았지만,
이번 PR에서 `ENABLE_CUDA` 조건으로 바뀌어 실제 device-only embedding
경로가 된다.

staging buffer를 키울 때 기존 buffer부터 `cudaFreeHost()`로 해제한 뒤
`cudaHostAlloc()`의 반환값을 확인하지 않고 capacity를 갱신한다. pinned
memory가 부족해 allocation이 실패하면, 뒤의 병렬 dequant loop는
null 또는 이미 해제된 `emb_stage`에 쓰고 H2D copy도 같은 pointer를
사용한다.

새 buffer allocation 성공을 먼저 확인한 뒤에만 기존 buffer와
교체해야 한다. 실패 시에는 capacity를 바꾸지 말고, 안전한 pageable
staging과 동기 copy를 쓰거나 오류를 호출자에게 전달해야 한다.
`cudaMemcpy`와 `cudaMemcpyAsync`의 반환값도 함께 확인하는 편이 안전하다.

### P3 — 수동 FP32→FP16 변환이 round-to-nearest-even을 구현하지 않음

위치:

- `nntrainer/cuda/cuda_fc_qint4.cpp:1283-1300`
- `nntrainer/cuda/cuda_fc_qint4.cpp:1345-1346`

`f2h()`는 버리는 부분의 최상위 bit가 1이면 나머지 bit와 현재 mantissa의
짝수·홀수 여부를 보지 않고 항상 1을 더한다. 이는 IEEE
round-to-nearest-even이 아니라 tie를 항상 위로 올리는 방식이다.

예를 들어 정확한 중간값 `1.00048828125`는 표준 FP16에서 짝수 쪽인
`0x3c00`이 되어야 하지만 이 함수는 `0x3c01`을 만든다. `exp >= 31`
분기도 NaN을 infinity로 바꾼다. CPU fallback의 `_FP16` cast와 GPU
logit이 1 ULP씩 달라질 수 있고, 가까운 vocab logit에서는 token 선택에
영향을 줄 수 있다.

CUDA의 `__float2half_rn()`과 `__half_as_ushort()`를 사용하거나
guard/sticky/tie-even bit를 포함해 변환을 완성해야 한다.

## 정상으로 확인한 부분

- Q6_K block의 128-byte `ql`, 64-byte `qh`, 16개 signed scale, FP16
  block scale layout이 기존 구현과 일치함
- 16개 lane이 block당 256개 hidden 원소를 중복·누락 없이 처리함
- `sc[0/2/4/6]` 선택과 `ql/qh`의 6-bit 복원이 OpenCL kernel과 일치함
- 홀수 vocab의 마지막 두 번째 row는 계산·저장을 범위 검사함
- `hidden % 256 != 0`을 kernel 진입 전에 거부함
- non-CUDA build에서 새 include와 실행 block이 전처리로 제외됨

## 이전 PR에서 이어진 차단 문제

#4117에서 지적한 graph allocator 선택 문제는 아직 남아 있다. CUDA node가
있어도 graph가 CPU allocator를 받으면 새 Q6_K fast path의
`dev_accessible()` 조건 자체가 false가 되어 이 PR의 핵심 기능이
활성화되지 않는다. GitHub의 같은 자동 리뷰 thread도 현재 head에서

## 테스트 공백

고유 변경에는 자동 test가 없다. PR 본문의 RTX 5060 수동 검증만으로는
bias, multi-batch, device-only 실패 fallback과 pinned allocation 실패를
검증할 수 없다.

최소한 다음 테스트가 필요하다.

- random Q6_K weight를 CPU reference와 비교하고 홀수 vocab도 포함
- bias on/off와 `batch > 1`
- kernel 등록·launch 실패를 주입한 device-only fallback
- host-backed weight/output을 CUDA kernel 진입 전에 거부하는지 확인
- pinned staging allocation/copy 실패 주입
- FP32→FP16 tie, subnormal, infinity, NaN 변환

현재 환경에는 CUDA toolkit과 GPU가 없어 runtime 검증은 수행하지 못했다.
