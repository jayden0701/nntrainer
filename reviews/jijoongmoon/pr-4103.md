## Review summary

이 PR은 OpenCL 소비자가 필요로 하는 소스 헤더 5개를 Meson 설치 목록에
추가하고, 라이브러리 빌드에서만 사용하는 생성 커널 문자열 헤더를 설치
대상에서 제거한다.

변경된 설치 헤더와 include 관계를 확인했다.

- `cl_context.h`가 포함하는 `opencl_buffer_manager.h`와
  `opencl_context_manager.h`의 의존성에서 새로 설치되는
  `opencl_buffer.h`, `opencl_device_info.h`가 필요하다.
- `blas_kernels.h`와 `attention_kernels.h`는 라이브러리 소스 및 템플릿이
  직접 포함하며, 각각 필요한 OpenCL 공개 헤더를 포함한다.
- 생성된 `cl_kernels.h` 및 커널별 문자열 헤더는 라이브러리 구현에서만
  사용된다. 이를 `nntrainer_headers`에서 제거해도 생성 `.cpp`와
  `cl_kernels/*`의 빌드 디렉터리 include 경로는 유지된다.
- 제거 대상 중 `swiglu.h`는 CausalLM의 동명 레이어 헤더와 실제로 충돌할
  수 있으므로 설치 대상에서 빼는 방향이 타당하다.

## Findings

### P1 — Tizen GPU devel 패키지 manifest에 새 설치 헤더가 누락됨

위치:

- `nntrainer/opencl/meson.build:14`
- `nntrainer/tensor/cl_operations/meson.build:11`
- 관련 manifest: `packaging/nntrainer.spec:737`

이 PR은 OpenCL 활성 빌드에서 5개 헤더를 새로 설치하지만,
`packaging/nntrainer.spec`의 `%if %{with gpu}` / `%files devel` 목록에는
이를 추가하지 않는다.

- `opencl_buffer.h`
- `opencl_loader.h`
- `opencl_device_info.h`
- `blas_kernels.h`
- `attention_kernels.h`

RPM/GBS 패키징은 설치되었지만 어떤 `%files`에도 속하지 않은 파일 때문에
실패할 수 있다. 빌드 설정이 이를 허용하더라도 devel RPM에는 새 헤더가
들어가지 않아, clean install 소비자 빌드를 고치려는 PR 목적이 Tizen
GPU 패키지에서는 달성되지 않는다.

`%{with gpu}` 블록의 devel 파일 목록을 실제 Meson 설치 경로에 맞춰
갱신해야 한다.
