# PR #4112 review

- PR: [nntrainer/nntrainer#4112](https://github.com/nntrainer/nntrainer/pull/4112)
- Title: `[opencl] Add the GPU attention/RoPE/KV kernels + GLU whole-ops, fix rmsnorm tails`
- Author: `jijoongmoon`
- Reviewed head: `08ff4cdd93cfb14ed28c6766bd5afad363c63fce`
- Review date: 2026-07-28
- Verdict: **Request changes — PR 고유 correctness blocker 5건**

## Review summary

이 PR은 #4110 위에 fp16 attention/RoPE/KV kernel, GLU whole-op, RMSNorm과
addition 변경을 추가한다. #4110 대비 고유 delta는 27개 파일, 7,038개 추가
라인이다.

핵심 attention 경로에는 cached/chunked causal 위치 계산과 non-causal
accumulation 오류가 있고, 명시적으로 지원하는 out-of-order queue에서는
pipeline command 사이의 의존성이 없다. process-global scratch의 image view도
backing buffer 교체 후 무효화되지 않는다. 새 GLU whole-op은 kernel 등록 함수가
호출되지 않아 첫 dispatch부터 빈 vector를 인덱싱한다.

## Findings

### P1 — GeGLU/SwiGLU whole-op kernel을 등록하지 않고 빈 vector를 인덱싱함

위치:

- `nntrainer/tensor/cl_operations/geglu_cl_op.cpp:55`
- `nntrainer/tensor/cl_operations/geglu_cl_op.cpp:316`
- `nntrainer/tensor/cl_operations/swiglu_cl_op.cpp:52`
- `nntrainer/tensor/cl_operations/swiglu_cl_op.cpp:260`
- `nntrainer/tensor/cl_operations/cl_compute_ops.cpp:97`

새 `ClComputeOps::geglu()`와 `swiglu()`는 각각 새 whole-op으로 전달되지만,
dispatch 함수는 file-local `getLayerKernelPtrs()[0]`을 즉시 읽는다.
이 vector를 채우는 `registerGeGLUClKernels()`와
`registerSwiGLUClKernels()`는 정의만 있고 호출처가 없다.

기존 `SwiGLULayerCl::registerClKernels()`는 다른 class/TU의 별도 static
vector를 채우므로 이 문제를 해결하지 않는다. 따라서 새 API가 처음 호출되면
out-of-bounds access로 undefined behavior/crash가 난다. 두 등록 함수를
`ClContext` 초기화에 연결하거나 whole-op이 최초 사용 시 안전하게 kernel을
등록해야 하며, CPU 대비 FP32/FP16 dispatch 테스트가 필요하다.

### P1 — cached/chunked causal attention이 query의 절대 위치를 잃음

위치:

- `nntrainer/tensor/cl_operations/cl_kernels/flash_attention.cl:106`
- `nntrainer/tensor/cl_operations/cl_kernels/flash_attention.cl:250`
- `nntrainer/tensor/cl_operations/cl_kernels/flash_attention.cl:467`
- `nntrainer/tensor/cl_operations/cl_kernels/two_conv_attention.cl:96`
- `nntrainer/tensor/cl_operations/cl_kernels/two_conv_attention.cl:628`
- `nntrainer/tensor/cl_operations/cl_kernels/two_conv_attention.cl:793`
- `nntrainer/tensor/cl_operations/cl_kernels/two_conv_attention.cl:1072`

이 경로들은 causal upper bound를 `n <= m`으로 계산한다. 하지만 query가
cache의 마지막 `M`개 row이고 cache 길이가 `N_kv`라면 local row `m`의
절대 위치는 `(N_kv - M) + m`이다. 같은 파일의 OHWI/flash block-query
variant는 이미 이 `q_off` 공식을 사용한다.

예를 들어 `M=1`, `N_kv=128`인 causal continuation에서 현재 구현은 key 0만
보고, 올바른 query는 key 0..127을 모두 봐야 한다. `q_off=N_kv-M`을 모든
variant에 일관되게 적용하거나 wrapper가 `M==N_kv`만 허용해야 한다.
`M=1`, chunked `1<M<N_kv`, square prefill을 variant별로 CPU 결과와 비교해야
한다.

### P1 — OHWI V-image 경로가 `causal=false`에서도 causal prefix만 합산함

위치:

- `nntrainer/tensor/cl_operations/cl_kernels/two_conv_attention.cl:899`
- `nntrainer/tensor/cl_operations/cl_kernels/two_conv_attention.cl:967`
- `nntrainer/tensor/cl_operations/attention_kernels.cpp:2313`

`sv_matmul_f16_ohwi_img`와 `_tm2`는 `causal` 인자를 받지 않으면서 항상
`(N_kv-M)+m`까지로 V texel 수를 줄인다. host wrapper는
`causal=false`를 허용하지만 K3에 그 값을 전달할 방법이 없다.

따라서 non-causal `M=N_kv=128`의 row 0은 softmax가 128개 key 전체에 대해
계산된 뒤에도 SV 단계에서 첫 8개 V만 곱한다. 나머지 probability mass가
사라져 출력이 잘못된다. K3에 causal flag를 전달해 prefix cap을 조건부로
적용해야 한다.

### P1 — legacy out-of-order queue에서 upload → QK → softmax → SV 순서가 없음

위치:

- `nntrainer/opencl/opencl_command_queue_manager.cpp:128`
- `nntrainer/tensor/cl_operations/attention_kernels.cpp:1190`
- `nntrainer/tensor/cl_operations/attention_kernels.cpp:1250`
- `nntrainer/tensor/cl_operations/attention_kernels.cpp:1268`
- `nntrainer/tensor/cl_operations/attention_kernels.cpp:1312`
- `nntrainer/tensor/cl_operations/attention_kernels.cpp:1374`

`NNTR_GPU_SVM_POOL=0`은 문서화된 legacy 경로로 out-of-order command queue를
만든다. 새 staged attention wrapper들은 nonblocking upload와 세 kernel을
모두 event wait-list 없이 enqueue한다. 마지막 `clFinish()`나 blocking
read는 전체 완료만 기다릴 뿐, OOO queue에서 producer-consumer 순서를
만들지 않는다.

그 결과 QK가 upload보다 먼저, softmax가 QK보다 먼저, SV가 softmax보다 먼저
실행되어 초기화되지 않은 input/scores를 읽을 수 있다. 각 stage를 event
chain/barrier로 연결하거나 이 경로에서는 in-order queue를 강제해야 한다.
`NNTR_GPU_SVM_POOL=0` 구성도 수치 테스트에 포함해야 한다.

### P1 — backing buffer 교체 후 cached image가 이전 K/V를 계속 가리킴

위치:

- `nntrainer/tensor/cl_operations/attention_kernels.cpp:124`
- `nntrainer/tensor/cl_operations/attention_kernels.cpp:1369`
- `nntrainer/tensor/cl_operations/attention_kernels.cpp:1386`
- `nntrainer/tensor/cl_operations/attention_kernels.cpp:1805`

`tca_ensure()`는 shared `q/k/v` buffer가 부족하면 기존 handle을 release하고
더 큰 buffer로 교체한다. 그러나 그 buffer로 만든
`sc.q_image/k_image/v_image`는 무효화하지 않는다. image wrapper의 cache
key도 shape metadata만 비교하고 backing handle/generation은 비교하지 않는다.

따라서 image call 뒤 다른 variant나 더 큰 shape가 shared buffer를 교체하고,
원래 shape로 다시 image call을 하면 upload는 새 buffer에 쓰지만 kernel은
이전 buffer를 retain한 cached image에서 오래된 Q/K/V를 읽는다. buffer
재할당 시 모든 dependent image view를 release하거나 cache key에 backing
handle/generation을 넣어야 한다. 서로 다른 shape/variant를 번갈아 호출하는
회귀 테스트가 필요하다.

## Residual risk

로컬 OpenCL hardware에서 실행하지 못했다. 추가로 K/V scatter/gather wrapper는
`position + M <= max_S`를 검증하지 않아 capacity 경계에서 device OOB
read/write 가능성이 있고, SVM-direct addition은 const input을 unmap한 뒤
result만 다시 map한다. FP16 RMSNorm layer의 기존 dispatch도 hidden width를
그대로 local size로 사용하므로 큰 LLM width에서 별도 검증이 필요하다.
